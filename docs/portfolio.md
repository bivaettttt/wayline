# Wayline · Материал для портфолио

**Задача.** Изменение прогнозного времени одного рейса может сделать весь маршрут непригодным. Путешественнику нужны объяснение и допустимые варианты. Операционному аналитику нужна история доставки и принятия обновления.

**Вклад.** Спроектировал контракты времени, правила MCT, состояния рейса и инцидента, границы интеграционной транзакции, политику повторов и трассируемость проверок.

**Требования.** Хранить время в UTC, отображать локальное время аэропорта, сохранять план, прогноз и факт, применять обновления по версии, пересчитывать связанные поездки и проверять альтернативы на MCT.

**Архитектура.** FastAPI и PostgreSQL отвечают за поездки и проекцию статусов. Отдельный провайдер хранит поток событий. Polling worker доставляет события по HTTP. Один коммит сохраняет курсор, историю, проекцию, оценку и уведомление.

**Реализация.** Объяснимая оценка пересадки и ограниченный поиск по датированным сегментам. Снимок результата хранит версию расписания. Интерфейс показывает пересадки, причину риска, допустимые маршруты и состояние источника.

**Проверка.** Показать задержку, которая сокращает пересадку с 95 до 35 минут при MCT 60 минут. Затем показать альтернативы и сопоставить событие провайдера с версией в истории. Для технической части воспроизвести повтор, конфликт, тайм-аут и восстановление из сохранённого курсора.
